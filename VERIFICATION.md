# NoteMark 1.1.9 verification

## Offline addition times and ordering

Notes retain their original creation time. Newly added checklist items store createdAt on the first saved input, before Add is pressed. Later edits and completion changes preserve that timestamp. Reconnection sorts new additions by their recorded creation time, oldest first, with a stable item-ID tie-break. Local clock accuracy matters; no server-arrival time replaces creation time. Earlier checklist items have no recoverable historical timestamps and retain their previous sequence.

The dashboard defaults to Oldest first; other sorts remain available and the chosen preference persists locally. Pinned notes retain priority. Every checklist row has a direct mouse/touch drag handle. A blue insertion line previews the destination; near-edge dragging scrolls within the section. Drops save once, atomically. Escape, pointer cancellation, leaving the section, focus loss and editor refresh cancel the gesture. Show times displays addition times; Alt+Up/Down and handle arrow keys retain keyboard access. Moves stay within unfinished or Completed groups. By time resets custom order. Explicit ordering/reset metadata is encrypted and included in backups; it survives restart and sync. A later recorded explicit reorder wins concurrent reorder conflicts, using an identity tie-break. Unrelated text edits do not reset order. New unpositioned items append chronologically after custom positions. Legacy sequence metadata lets By time restore the original order of older items without inventing timestamps.

Touch input is emulated in Chromium; it is not a physical Android touch test.

Java/JavaScript phone-host integration now verifies offline timestamps and custom order through the real Java socket server, persistence after server restart, and resetting order. Startup/recovery, package assets, certificate checks, terminal deletions and backup cancellation remain covered. Gradle tracks shared JS and APK inputs so these checks cannot silently reuse results from an earlier APK.

## Compatibility and limitations

Android is 1.1.9/code15 with the existing com.miranotes.app package, signer, WebView origin, storage key and phone certificate identity. Windows 1.1.9 retains its application ID, upgrade identity and existing user-data directory. Update both apps: earlier clients do not retain the new optional timestamp/order metadata when rewriting a note. No server API, encryption or pairing-code format changed; both existing hosting implementations store the encrypted payload unchanged.

Existing notes/pairing were not modified during isolated tests. No new physical POCO installation or launch test was performed. Android framework tests do not execute Chromium on a physical phone. Windows remains unsigned. Phone hosting still requires the hosting app to stay visible; internet hosting remains undeployed. Backups contain readable notes. Private notebooks, pairing codes, signing keys and profiles are excluded from delivered ZIPs.
